# SegmentDesk 使用说明

## 安装与首次运行

从源码运行或构建，请参阅 [Flutter 桌面工程](../desktop/README.md)。从 [GitHub Releases](https://github.com/evan-dev0608/segmentdesk/releases) 下载对应平台的压缩包或安装程序。

- **Windows 安装版（推荐）**：运行 `SegmentDesk-windows-x64-setup.exe`。默认安装到当前用户目录，无需管理员权限。可从开始菜单启动，在 Windows 应用设置中卸载。
- **Windows 免安装版**：解压 `SegmentDesk-windows-x64-no-install.zip` 的完整内容，再运行 `stream_download.exe`。保留同目录的 DLL 和 `data` 文件夹。免安装版不含 `native_import.json` 与 Chrome Native Messaging 注册项，浏览器一键导入请改用扩展的「复制」。
- **macOS / Linux**：macOS 解压后打开 `SegmentDesk.app`，Linux 解压后运行 `stream_download`。macOS 包尚未做 Developer ID 签名和公证。

Windows 的安装版和免安装版共用当前用户的核心和设置。安装程序目前未签名，Windows 可能显示发布者提示。

核心安装需要能访问 GitHub，并使用系统上的 `curl` 和 `tar`。媒体任务通常需要 FFmpeg。客户端启动下载时会探测 PATH 中的 ffmpeg，并把找到的路径显式传给核心；若未找到，会在任务日志中给出提示，由核心按自身配置继续判定。安装后，在终端运行 `ffmpeg -version` 可检查 PATH 是否生效。如果修改了 PATH，重新打开客户端。

通过 GitHub 官方发行页回退安装核心时，发行页不提供文件大小和 SHA-256 信息，设置页会标注「本次未做完整性校验」；通过 GitHub API 正常安装则会按可用元数据执行校验。

启动检查发现缺少核心时，打开 **设置 → 下载核心 → 在线下载**。也可用文件选择按钮指定本地核心，或直接在路径框中编辑。FFmpeg 的路径和版本同样在设置页显示，Windows x64 支持在线下载（源为 gyan.dev 的 essentials 构建，先校验 SHA-256 再缓存），其他平台的下载按钮可见但禁用。设置保存时会校验填写的路径是否可执行。客户端自身通过 **设置 → 客户端 → 检查客户端更新** 查询正式版；Release 版启动时也会自动检查。

**核心版本差异**：高级选项、点播分段和配置隔离都按已安装核心的 `--help` 动态判断，不会硬编码参数。官方 `v0.6.0-beta`（20260628）比上游主分支旧，缺少 `--config` / `--no-config`、`--cookies`、`--vod-*-parts` 三件套以及 4 个工具子命令；因此用它时不会出现分段多选与工具命令，但选轨与常规下载仍可用。客户端可读取 IPTV 频道列表，实际按频道下载需要核心支持 IPTV 解析。选轨下拉会依据 `Codecs` / `Resolution` / `Role` 推断轨道类型，兼容不输出 `MediaType` 的旧版元数据。功能缺失时先核对核心版本，不要当作客户端故障。

## 下载链接

1. 点击右上角 **新建下载**。
2. 粘贴完整的 HTTP(S) 媒体清单链接，例如 HLS 的 `.m3u8` 或 DASH 的 `.mpd`。普通视频播放页面需要先取得媒体清单链接。
3. 选择保存目录，可选填文件名，然后点击 **开始下载**。
4. 在任务列表选中该任务，查看状态和日志。任务结束后可打开输出目录。失败任务可以用原设置重试。

进度条的连续刷新会折叠为一行，带时间戳和级别的正式日志始终完整保留；FFmpeg 等不带日志前缀的原始输出也不会被过滤掉。

客户端不再把「退出码 0」直接等同于完整成功。若日志里出现上游的 ERROR 级记录或明确的失败文案，任务会标为 **完成（有错误）** 并保留重试入口。若在「高级选项」中把 `--check-segments-count` 设为 `false`，核心会静默移除缺失分片，客户端会在任务日志中提示风险，并把状态标为 **已完成（未校验分片数）**；此时请自行核对输出文件是否完整。

普通下载会使用自动选轨。可在 **设置 → 下载偏好** 中修改默认目录与输出格式（MKV / MP4 / TS / 分别保存轨道，默认为 MKV；选择「分别保存轨道」时不混流）。

## 本地清单与高级选项

打开 **新建下载**，可粘贴链接或通过文件选择器打开本地清单。点击 **高级选项** 会带入已填写的来源、目录和文件名。使用搜索框查找参数说明，例如请求头、限速、录制时长或选轨筛选；地址框下方还可图形化读取轨道、挑选点播分段与 IPTV 频道。控件来自已安装核心的帮助，因此不同版本的可用设置可能不同。

以下示例都在 **新建下载 → 高级选项** 中操作。先填链接或选本地清单，搜索表中的参数，把示例值填进对应控件，最后点击 **开始下载**。参数名用于搜索，值直接填到输入框。

| 场景 | 参数 | 填写示例 |
| --- | --- | --- |
| 请求需要 Referer | `--header` | 填 `Referer: https://example.com/`。多个请求头用「添加一项」逐条填写。 |
| 使用本机 HTTP 代理 | `--custom-proxy` | 填 `http://127.0.0.1:7890`。 |
| 调整下载线程和限速 | `--thread-count`、`--max-speed` | 分别填 `8` 和 `2M`。 |
| 只下字幕 | `--sub-only` | 选择「启用」，自动选轨留在「默认」或选择「关闭」。 |
| 只选英语音轨 | `--select-audio` | 填 `lang=en:for=best`。如果也要下载视频，再为 `--select-video` 填 `best`。自动选轨留在「默认」或选择「关闭」。 |
| 下载指定时间范围 | `--custom-range` | 填 `00:05:00-00:20:00`，表示第 5 分钟到第 20 分钟。 |
| 录制直播 30 分钟 | `--live-record-limit` | 填 `00:30:00`，让核心在达到时长后结束录制。 |
| 混流为 MKV 并加入本地字幕 | `--mux-after-done`、`--mux-import` | 分别填 `format=mkv` 和字幕文件的完整路径。 |

普通「新建下载」会使用设置里的输出格式。通过「高级选项」运行时，如果需要混流，请在该任务中填写 `--mux-after-done`。支持配置文件和 Netscape Cookie 文件的核心会显示 `--config` 和 `--cookies`，可直接浏览选择。详细语法见 [上游中文文档](https://github.com/nilaoda/N_m3u8DL-RE#命令行参数)。

**关于全局配置**：上游默认会读取 `%APPDATA%/N_m3u8DL-RE/config.conf`，并按「命令行 > 配置 > 默认」覆盖参数，界面上看不到这些注入值。客户端只有在核心帮助确实列出 `--no-config` 时才会追加该参数，让任务只受界面上的设置影响；旧发行版没有这个参数时会跳过隔离，并在任务日志中提示全局配置可能生效，而不是把未知参数塞给核心。若确实需要沿用全局配置，在「高级选项」中填写 `--config` 指定配置文件即可，客户端此时不会再追加 `--no-config`（两者同时传入会被核心判定为冲突）。「检测环境（doctor）」命令例外，它需要读取全局配置才能给出完整的环境报告。

### 图形化选轨、选段与 IPTV 频道

在 **新建下载 → 高级选项** 的地址框下方，有三个按钮；它们只在当前核心提供 `--select-video` 时可用。选择结果会回填到表单，点 **开始下载** 前仍可手动修改。

- **读取轨道**：先填好链接或本地清单，再点此按钮。客户端让核心以 `--skip-download --write-meta-json true` 在临时目录只解析清单，读取 `meta.json` 与 `meta_selected.json`，然后弹出选择窗口。窗口分别列出视频、音频、字幕下拉框；选择任一条会生成精确的 `url=...:for=best` 表达式并关闭自动选轨。核心支持 `--vod-drop-parts` 且清单含多个点播分段时，还会列出每段的编号和时长，取消勾选的段会转成 `--vod-drop-parts 0,2` 这样的排除值。预览最多等待 45 秒，临时目录用后即删。
- **本地 IPTV**：选择一个 M3U/M3U8 播放列表，勾选要下载的频道，客户端会把它设为下载来源并生成 `name=^频道A$|^频道B$:for=all`。
- **远程 IPTV**：在地址框填 M3U 链接后点此按钮。会沿用表单里的 `--header`、`--cookies`（Netscape 格式）、`--custom-proxy` 与 `--use-system-proxy`，限制 8 MiB 和 20 秒。远程拉取使用客户端内置的网络栈，不需要系统 `curl`。

M3U 判定与上游 `IPTVExtractor.IsPlaylist` 对齐：列表需以 `#EXTM3U` 开头，且含有 `#EXTGRP:`、`#EXTINF:-1` 或 `tvg-*` / `group-title` 属性之一；含 `#EXT-X-` 标签的会被视为 HLS 并拒绝。这样可避免「界面列出了频道、核心却把清单当 HLS 处理」。频道名中的正则元字符会被转义，冒号写成 `\:`，以适配核心的复合选轨表达式。


## 外观与故障排查

- 在 **设置 → 外观** 选择主题色，或切换浅色、深色与跟随系统。保存后会应用到当前窗口，并在重启后保留。
- **核心安装失败**：查看窗口底部的错误信息，确认网络能访问 GitHub 官方发行页，并确认 `curl` 和 `tar` 可用。
- **找不到 FFmpeg**：确认 `ffmpeg -version` 可执行，再重启客户端；也可在 **设置 → FFmpeg** 直接填写可执行文件完整路径（Windows x64 可点「在线下载」）。
- **看不到某项工具或参数**：查看核心版本并尝试检查更新。官方发行版的功能可能少于上游主分支；缺少 `--no-config` 时客户端也会跳过配置隔离并给出日志提示。
- **「读取轨道」失败**：确认核心已安装、地址可访问且表单里的请求头与 Cookie 正确；错误信息会附带核心输出的最后几行。部分直播清单不提供轨道元数据或分段信息，此时只能使用自动选轨。
- **IPTV 频道列表为空**：确认清单满足核心的 IPTV 判定条件（见上文），且频道 URL 是 HTTP(S)；简单 M3U 会被核心当成 HLS，客户端会提前拒绝。
- **状态是「完成（有错误）」或「已完成（未校验分片数）」**：核心返回了退出码 0，但日志里有错误记录，或本次关闭了分片数量校验。展开任务日志确认是可选轨道失败还是主文件受损，必要时用原设置重试，并核对输出文件。
- **任务失败**：在任务列表中选中该任务查看退出码和日志。提交问题时可附上系统、客户端版本、核心版本和经过脱敏的日志。
